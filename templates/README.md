# 输出模板（随仓库分发，远端可见）

四类短线分析产出 + 交互看板骨架。模板是**结构契约**：逐节填充、禁止增删节、禁止改顺序，
杜绝同一场景每次输出内容漂移。

| 场景 | 模板 | 调用技能 | lint type |
|---|---|---|---|
| 晚间整体复盘 | `dt/market-review.md` | dt-review | review |
| 单票深度分析 | `dt/stock-analysis.md` | dt-monitor（深度模式）/ 主会话 | stock |
| 板块内标的对比 | `dt/sector-compare.md` | dt-sector | sector |
| 盘前简报 | `dt/pre-briefing.md` | dt-briefing | briefing |
| 交互看板骨架 | `dt/dashboard.html` | 各技能看板产出的统一基座 | （--dashboard 检查） |

## 填写规则（对全部模板生效）

1. 模板中 `{...}` 为占位符，必须全部替换；交付物中残留 `{{` / `TODO` 视为未完成。
2. 取不到的数据写「数据缺失（原因）」，禁止估算、编造、沿用旧值、用"约/大概"模糊带过。
3. 表格行数可少（没内容就少几行），表头与列结构不得变。
4. 每个数字都要能溯源：附录A 列出数据 → 工具 → 落盘文件/当次返回 的对应关系。
5. 填完后自检：`python tools/report_lint.py <报告路径> --type <类型> [--dashboard <看板.html>]`，
   全部通过才算交付。
6. 依据条目编号（DT-xx-nnn 等）只出现在 md 报告与台账；用户可见看板用自然语言
   （规则名 + 一句话说明）。

## 版本约定

- 模板改动 = 文件头版本号 +1（`v1` → `v2`），报告头注明所用版本。
- 报告一旦存档不回改；模板升级只影响后续产出，历史报告保持原样作为对照样本。
